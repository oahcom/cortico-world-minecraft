**新建 `src/backoff.ts`**，移植 Amaidesu 的 `ExponentialBackoff` 模式：

- `nextDelayMs(): number` = `min(base * factor**n, cap)`；**n 封顶 `maxExponent`（默认 30）**——这是 Amaidesu 踩过的坑：调用次数无界增长时 `factor**n` 浮点溢出为 Infinity，`min(Infinity, cap)` 恰好兜住，但中间比较与日志会失真，且无封顶时一旦 cap 逻辑改动，异常会逃出重连循环终止采集——所以显式封指数。
- `reset(): void` 成功即归零（连上了就重置，这是关键语义）。
- 构造参数：`baseMs / factor / capMs / maxExponent`，全部可注入、带默认值（参考 5s 起步 60s 封顶和 5→10→20→40→60 两种用法）。
- 纯类，无 IO，无定时器（延迟由调用方 `setTimeout(backoff.nextDelayMs(), ...)` 消费）。

**三处接入**：每处把现有裸延迟换成 backoff 实例；**成功事件（服务器 listening / bot spawn）处调用 `reset()`**。

**新建 `tests/backoff.test.ts`**（node:test，纯单测）：序列正确性（5→10→20→40→60 封顶）、reset 归零、maxExponent 防 Infinity、cap 生效。参考 Amaidesu 的同名测试思路。
